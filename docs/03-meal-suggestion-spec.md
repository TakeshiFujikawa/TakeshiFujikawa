# 3. 写真からの献立提案機能 — 仕様

> 本機能は「2026年5月30日からの健康管理プログラム」（1年間で-15kg、同時に
> 筋力アップ・健康な身体づくりを行う）での実利用を主軸に設計する。
>
> 以下は、ユーザー本人から共有された**実際の運用ルール・確定仕様**である
> （2026年5月14日時点の体組成データを含む）。アプリのMVP実装前であっても、
> このルールに沿って毎日チャット上で同等の体験を提供できるようにしておく。

## 3-0. 確定仕様：日次の運用フロー

ユーザーは毎日、以下の3種類の情報を共有する。これを起点に、
**毎食5つの献立提案**と、体組成データに基づく**課題の整理**を行う。

| ユーザーが毎日共有する情報 | 内容 |
|---|---|
| 📸 食事・飲み物の記録 | その日食べた・飲んだもの（なるべく全食）の写真＋文字での説明 |
| ⚖️ Health Planetのデータ | 体組成計の表示画面のスクリーンショット（体重・体脂肪率・内臓脂肪レベル等） |
| 💪 運動の有無 | その日運動したかどうか（行った場合は内容も） |

これに対しアプリ（またはチャット）側は、以下を返す。

1. **毎食5案ずつの献立提案**（朝食・昼食・夕食・間食、それぞれ5案を理由付きで提示）
2. **体組成データに基づく課題の整理**（「最優先で改善すべき点」「良い点」の形式で、
   体組成計の各指標を踏まえて整理し、進捗の解釈を添える）

## 3-0-1. 体組成データの基準値（2026年5月14日時点・参考例）

ユーザーから共有された開始前の体組成データを、課題整理のベースラインとして保持する。
今後、Health Planetのスクリーンショットが届くたびにこの基準と比較し、
「改善しているか／注意が必要か」を判定する材料とする。

| 項目 | 数値 | 評価 |
|---|---|---|
| 体重 | 89.15 kg | — |
| 体脂肪率 | 31.40% | 🔴 肥満（目標：25%以下） |
| 筋肉量 | 58.00 kg | 🟢 標準 |
| 筋肉スコア | 1 | — |
| BMI | 28.8 | 🟠 肥満1度 |
| 筋質点数 | 89 | 🟢 高い |
| 内臓脂肪レベル | 15.5 | 🔴 過剰（生活習慣病リスク大） |
| 推定骨量 | 3.20 kg | 🟢 標準 |
| 体水分率 | 45.5% | — |
| 基礎代謝量 | 1,733 kcal | 🔴 少ない |
| 体内年齢 | 53才 | ⚠️ 要注意 |

**最優先で改善すべき点**：内臓脂肪レベル（過剰→生活習慣病リスク）／体脂肪率
（目標25%以下）／基礎代謝の低さ（筋肉の「質」を活かして底上げが必要）

**良い点**：筋肉量は標準範囲を維持／筋質点数89は高評価（質の良い筋肉を土台に、
量と代謝を伸ばせる余地が大きい）

→ 「筋肉の質は良いが、内臓脂肪と基礎代謝に課題がある」状態。
**1年で-15kg＋筋力アップ**という目標と方向性は完全に一致しており、
急激な減量よりも「内臓脂肪を落としながら筋肉の質と量を底上げする」
アプローチ（条件5のボディリコンポジション方針）が最適となる。

## 3-1. 機能概要

ユーザーが食事の写真と文字、Health Planetのデータ、運動の有無を共有すると、
1. 何を食べた・飲んだか（料理名・推定カロリー・PFC）を記録し、
2. 体組成データの推移と本人の状態（回復・運動量・残りカロリー枠・アレルギー・目標）を踏まえて、
3. **毎食5案ずつ、「次に何を食べるとよいか」を具体的に提案し、**
4. **体組成データをもとに「課題の整理」を継続的に提示する**

「記録して終わり」のヘルスプラネットに対し、本機能は
「記録 → 解析 → 次のアクションの提示 → 継続的な課題整理」までを
1つの日次サイクルとして完結させる点が差別化ポイント。

## 3-2. 処理フロー

```
① 共有
   └─ ユーザーが毎日：食事・飲み物の写真＋文字／Health Planetのスクリーンショット／
      運動の有無を共有する
② 画像・データ解析
   └─ 食事写真から料理・食材を認識し、品目・推定量・推定カロリー・推定PFCを算出
   └─ Health Planetのスクリーンショットから体組成の各指標を読み取り、基準値・前回値と比較
   └─ ユーザーは結果を確認し、必要なら品目や量を修正（学習データとしても活用）
③ 記録の確定
   └─ 食事ログ・体組成ログとして保存。1日の累計カロリー・PFC・栄養素バランス、
      体組成の推移を更新
④ 提案条件の評価（下記3-3）
   └─ プロフィール・当日のコンディション・直近の食事履歴・体組成の推移を突き合わせ、
      「毎食5案の献立提案」と「課題の整理」を生成
⑤ 提案・整理の提示
   └─ 朝食・昼食・夕食・間食それぞれについて、5案を理由つきで提示
   └─ 体組成データに基づく「最優先で改善すべき点」「良い点」を整理して提示
   └─ 必要に応じて「揚げ物が続いているので、夜は野菜多めに」等の軽いアドバイスを添える
```

## 3-3. 献立提案の判定条件（優先順位順）

以下を**この順で**評価し、上位の条件ほど提案内容に強く反映させる
（安全に関わる条件ほど優先度を高くする）。提案は**毎食5案ずつ**生成し、
それぞれに必ず理由を添える。

### 条件1：アレルギー・食事制限（最優先・絶対条件）

- プロフィールに登録されたアレルギー食材・宗教/思想上の制限
  （例：卵・乳・小麦・そば・落花生・甲殻類などの特定原材料、ベジタリアン／ヴィーガン／
  ハラール等）に該当する食材は、**提案候補から完全に除外する**。
- 過去の食事ログから「頻繁に避けている食材」を推定し、注意喚起の対象に加える
  （ただし完全除外はユーザー登録済みのアレルギーのみ。推定は「確認」に留める）。
- この条件は他のすべての条件より優先し、絶対に緩和しない。

### 条件1-2：個人の嗜好・苦手食材（ユーザー本人からの確定ルール）

医学的なアレルギーとは別に、**ユーザー本人が「食べられない／苦手」と明言したもの**も
絶対除外として扱う。逆に「好き」と明言されたものは、他の条件を満たす範囲で
優先的に取り入れる。これらはプロフィールの`food_preferences`として保持し、
新しいルールが共有されるたびに追記・更新する。

| 区分 | 内容 | 提案への反映 |
|---|---|---|
| 苦手・除外（確定） | 豆乳鍋 | **今後は提案候補から完全に除外する**（ユーザー本人からの明示的な依頼） |
| 好み（優先） | 鍋、焼魚 | 季節・条件が合えば優先的に候補へ取り入れる（3-4節の出力例にも反映） |

> 補足：今後も「これは苦手」「これは好き」という情報が共有されたら、
> その都度この一覧に追記し、即座に提案ロジックへ反映する
> （特に「除外」指定は条件1のアレルギーと同様、絶対に緩和しない）。

### 条件1-3：調味料・添加物の方針（記録・配慮事項）

ユーザーは**アミノ酸等の化学調味料をできるだけ使いたくない**という方針を持っている。
これを安全上の絶対条件（条件1）とは区別しつつ、提案・記録の両面で配慮する。

- 献立提案では、化学調味料に頼らず出汁・素材の味で仕上げられるメニュー
  （和食の鍋・焼き魚・煮物など）を優先的に候補へ含める。
- ユーザーが共有した食事内容に化学調味料・加工食品が含まれる場合は、
  日々の記録に「使用の有無」を残し（[DailyReview](04-data-model.md)に記録）、
  傾向が続く場合はやんわりと気づきを共有する（強い指摘・禁止はしない）。

### 条件2：当日のコンディション・回復状態（WHOOP由来の指標を活用）

回復スコアや運動負荷に応じて、提案する食事の方向性を変える。

| 状態 | 提案の方向性 |
|---|---|
| 回復スコアが低い／睡眠不足 | 消化に優しく栄養価の高い食事（具：タンパク質・ビタミン・ミネラルを意識、カフェイン/アルコール控えめ提案、消化に時間のかかる脂っこいものは避ける） |
| 高強度の運動をした日 | 運動後の回復を助ける食事（具：糖質＋たんぱく質の組み合わせ、水分・電解質補給の提案） |
| 運動量が少ない／休養日 | 摂取カロリーをやや抑えめにし、野菜中心・低GI食品を中心に提案 |

### 条件3：1日のカロリー目標と残り枠

- 基礎代謝＋活動量（Runkeeper由来の運動記録を含む）から1日の目標摂取カロリーを算出。
- 当日すでに記録された食事の合計カロリーを差し引き、「残りカロリー枠」を算出。
- 残り枠に収まる、かつ次の食事の標準的な配分（例：夕食なら1日の30〜35%目安）に
  近いカロリー帯の献立を優先して提案する。
- 残り枠が少ない場合は、低カロリーで満足感の高いメニュー（汁物・野菜中心等）を提案。

### 条件4：栄養バランス（PFC・主要栄養素）

- 直近の食事ログ（当日＋前日まで）を集計し、不足しがちな栄養素を補う方向で提案する。
  - タンパク質が不足気味 → 高タンパクなメニューを優先候補に
  - 野菜・食物繊維が不足気味 → 野菜量の多いメニューを優先候補に
  - 脂質・塩分・糖質が続けて多い → 控えめなメニューを優先し、軽い注意を添える
- 目安とする1日のPFCバランス（一般的な健康維持の範囲。プロフィールの目標で調整）：
  - タンパク質 13〜20% ／ 脂質 20〜30% ／ 炭水化物 50〜65%
  - 塩分は1日あたりの目安量を超えないよう、外食・加工食品が続いた場合は控えめな提案に寄せる

### 条件5：健康目標（プロフィール設定）

「減量」「維持」「増量・筋肉量アップ」のような単純な目標だけでなく、
**「減量」と「筋力アップ」を同時に狙う目標（ボディリコンポジション型）**にも対応する。
本アプリが主軸とする「2026年5月30日からの健康管理プログラム」（1年で-15kg＋筋力アップ）は
まさにこの型にあたるため、専用の方針を持たせる。

| 目標タイプ | 提案の方向性 |
|---|---|
| 減量のみ | カロリー収支をやや厳しめに、満足感重視（高食物繊維・高タンパク低脂質） |
| 増量・筋肉量アップのみ | カロリー・タンパク質をやや多めに配分 |
| 維持 | バランス重視で大きな偏りを作らない |
| **減量＋筋力アップ（ボディリコンポジション）** | 下記の方針で提案する |

**ボディリコンポジション型の提案方針**（本プログラムで採用）：

- カロリーは「緩やかな赤字」に留める（厳しい制限は避ける）。
  1年で-15kgという長期目標は、急激な制限よりも持続可能なペースに適している。
  目安として、1日の消費カロリーから大きく削りすぎない範囲（無理のない緩やかな
  カロリー収支）を基準とし、運動量に応じて微調整する。
- **タンパク質を最優先で確保する**（筋肉量の維持・向上のため、他の目標タイプよりも
  優先度を上げる）。トレーニングを行った日は特にタンパク質量を重視した献立を提案する。
- 筋力トレーニングを行った日・行う予定の日は、運動の前後で
  「炭水化物＋タンパク質」の組み合わせ（エネルギー補給と回復の両立）を提案する。
- 体重の増減だけでなく体脂肪率・筋肉量の推移（[2-2記録](02-screens-and-features.md)で
  表示）と突き合わせ、「順調に絞れているか」「筋肉量も保てているか」を踏まえた
  コメントを添える（例：「体重は順調に減っていますが、筋肉量を保つために
  今日はタンパク質をやや多めにとりましょう」）。

### 条件6：多様性・継続のしやすさ

「毎日同じ献立では飽きる」というユーザーからのフィードバックを踏まえ、
**多様性の確保を明示的な必須条件**として扱う。

- 直近数日と同じ料理・同じカテゴリ（揚げ物、麺類など）が続いている場合は、
  別カテゴリを優先的に提案し、マンネリ・栄養の偏りを防ぐ。
- 提案は「自宅で作れるメニュー」「コンビニ・外食での選び方」の両方を含む
  **5案**を用意し、ユーザーの状況（自炊できるか否か）に応じて選びやすくする。
- アイデアの幅を広げるため、以下のレシピサイトをバリエーションの参照元として活用する
  （提案時はサイト名を示し、ユーザーが気になれば実際のレシピを確認できるようにする）。

  | サイト | 特徴 |
  |---|---|
  | [キッコーマン ホームクッキング（健康レシピ）](https://www.kikkoman.co.jp/homecook/theme/popular/health.html) | 和食ベースの健康志向レシピ |
  | [oishi-kenko.com](https://oishi-kenko.com) | 健康・栄養系レシピ全般 |
  | [クックパッド](https://cookpad.com/jp) ／ [健康レシピ検索](https://cookpad.com/jp/search/健康レシピ) | レシピ全般・健康レシピの検索 |
  | [味の素 勝ち飯（免疫力）](https://www.ajinomoto.co.jp/kachimeshi/mennekiryoku/) | スポーツ栄養・コンディショニング向けレシピ |
  | [シダックス レシピ](https://recipe.shidax.co.jp) | 給食・健康配慮レシピ |
  | [全薬工業 ケーワン健康メニュー](https://www.zenyaku.co.jp/k-1ban/h_menu/) | 健康配慮メニュー |

- ユーザーの嗜好（条件1-2）と組み合わせ、「鍋」「焼き魚」のように好みが明言されている
  カテゴリは、レパートリーを広げる軸として優先的に活用する
  （例：鍋なら「豆乳鍋」以外の味付け・具材バリエーションを多く用意する）。

## 3-4. 毎朝のルーティン（必須・固定チェックリスト）

ユーザーは毎朝、以下を欠かさず実施している。これは「食事提案」とは別に、
**日次の固定ルーティンとして記録・確認する**項目として扱う
（提案や課題整理の際に、実施有無を踏まえた一言を添えてもよい）。

| 項目 | 内容 |
|---|---|
| 🥤 水 | 300ml |
| 🫗 純梅肉エキス | — |
| 💪 プロテイン | VALXプロテイン ＋ 🥥 ココナッツウォーター |
| 🌿 青汁 | DR.CLEANZ |
| 🫘 黒豆茶 | 1L（随時、1日を通して） |

- これらは1日の摂取カロリー・PFC計算にも反映する
  （特にプロテイン・ココナッツウォーターはカロリー・栄養価への影響があるため）。
- 実施有無や時間帯に変化があった場合は、課題整理やコンディションへの
  影響を確認する材料として記録しておく。

## 3-5. 提案・整理の出力イメージ

毎食5案の献立提案と、体組成データに基づく課題の整理を、以下のような形式で出力する。

```
🍽 今日の昼食のご提案（5案）

① 鶏むね肉と野菜の蒸し料理（約480kcal／たんぱく質35g）
   理由：内臓脂肪・体脂肪率の改善が最優先のため、高たんぱく・低脂質を意識。
        消化にも優しく、トレーニング後の回復もサポートします。

② サラダチキン＋具沢山味噌汁＋雑穀おにぎり（約540kcal）
   理由：コンビニでも揃えやすい組み合わせ。残りカロリー枠にちょうど収まります。

③ 鯖の塩焼き＋ひじきの煮物＋玄米（約560kcal／たんぱく質32g）
   理由：内臓脂肪レベルの改善に役立つ青魚・食物繊維を中心に構成しました。

④ 豆腐と野菜の鍋（約430kcal）
   理由：カロリーを抑えつつ満足感のあるメニュー。塩分も控えめにしています。

⑤ 全粒粉サンドイッチ（鶏むね肉・卵・野菜）＋スープ（約500kcal）
   理由：外出先でも準備しやすく、PFCバランスも崩れにくい構成です。

⚠ ひとことアドバイス：ここ2日、揚げ物が続いています。今日は油を使う調理を避けた
   ①③④のような選択がおすすめです。
```

```
📊 今日の課題の整理（Health Planetのデータより）

最優先で改善すべき点：
・内臓脂肪レベル 15.5（過剰）→ 生活習慣病リスク大。最優先で取り組みたいポイントです
・体脂肪率 31.4% → 目標は25%以下。緩やかなカロリー収支と運動の継続が鍵です
・基礎代謝量 1,733kcal（少ない）→ 筋肉の「質」は良いので、量を増やして底上げを

良い点：
・筋肉量は標準範囲を維持できています
・筋質点数89は高評価。質の良い筋肉を土台に、これからの伸びしろが大きいです

→ 前回（5/14時点）との比較：体重 -0.8kg／体脂肪率 -0.3pt と、緩やかに
  改善方向に向かっています。このペースを維持しましょう。
```

- 献立提案には常に「理由」を添える（ユーザーが納得して選べるようにするため。
  ブラックボックスの提案は信頼を失う）。
- アレルギー該当品は理由の説明なく**最初から候補に出さない**（誤って表示しない設計）。
- 課題の整理は「最優先で改善すべき点」「良い点」の2軸を必ず含め、可能であれば
  前回データとの比較（改善傾向か注意が必要か）を添えて、進捗を実感できるようにする。

## 3-6. 精度・運用上の注意点

- 画像認識の精度には限界があるため、**確認・修正のステップを必ず挟む**
  （特に分量推定はAIに頼り切らず、ユーザーが「少なめ／普通／多め」を選べる程度の補助に留める）。
- 推定カロリー・栄養価には誤差がある前提で、提案は「厳密な指示」ではなく
  「方向性の提案」というトーンに統一する（数値を絶対視させない）。
- アレルギー情報は安全に直結するため、プロフィール未設定の場合は機能利用前に
  必ず入力を促す（未入力のまま提案を出さない）。
