# 3. 写真からの献立提案機能 — 仕様

> 本機能は「2026年5月30日からの健康管理プログラム」（1年間で-15kg、同時に
> 筋力アップ・健康な身体づくりを行う）での実利用を主軸に設計する。
> アレルギー・栄養バランス等の判定基準そのものは、過去チャットの詳細が
> このセッションに引き継がれていないためAIが一般的な健康管理の観点で設計した。
> 実装時は実際のユーザー要件と突き合わせて調整してほしい。

## 3-1. 機能概要

ユーザーが食事の写真を撮るだけで、
1. 何を食べたか（料理名・カロリー・PFC）を自動記録し、
2. その記録と本人の状態（回復スコア・運動量・残りカロリー枠・アレルギー・目標）を踏まえて、
3. **「次の食事に何を食べるとよいか」を具体的に提案する**

「記録して終わり」のヘルスプラネットに対し、本機能は
「記録 → 解析 → 次のアクションの提示」までを1フローで完結させる点が差別化ポイント。

## 3-2. 処理フロー

```
① 撮影
   └─ 食事の写真を撮影（または既存の写真を選択）
② 画像解析
   └─ 料理・食材を画像認識し、品目・推定量・推定カロリー・推定PFCを算出
   └─ ユーザーは結果を確認し、必要なら品目や量を修正（学習データとしても活用）
③ 記録の確定
   └─ 食事ログとして保存。1日の累計カロリー・PFC・栄養素バランスを更新
④ 提案条件の評価（下記3-3）
   └─ プロフィール・当日のコンディション・直近の食事履歴を突き合わせ、
      「次の食事提案」と「注意点（あれば）」を生成
⑤ 提案の提示
   └─ 「次の食事はこれがおすすめ」を1〜3案、理由つきで提示
   └─ 必要に応じて「揚げ物が続いているので、夜は野菜多めに」等の軽いアドバイスを添える
```

## 3-3. 献立提案の判定条件（優先順位順）

以下を**この順で**評価し、上位の条件ほど提案内容に強く反映させる
（安全に関わる条件ほど優先度を高くする）。

### 条件1：アレルギー・食事制限（最優先・絶対条件）

- プロフィールに登録されたアレルギー食材・宗教/思想上の制限
  （例：卵・乳・小麦・そば・落花生・甲殻類などの特定原材料、ベジタリアン／ヴィーガン／
  ハラール等）に該当する食材は、**提案候補から完全に除外する**。
- 過去の食事ログから「頻繁に避けている食材」を推定し、注意喚起の対象に加える
  （ただし完全除外はユーザー登録済みのアレルギーのみ。推定は「確認」に留める）。
- この条件は他のすべての条件より優先し、絶対に緩和しない。

### 条件2：当日のコンディション・回復状態（WHOOP由来の指標を活用）

回復スコアや運動負荷に応じて、提案する食事の方向性を変える。

| 状態 | 提案の方向性 |
|---|---|
| 回復スコアが低い／睡眠不足 | 消化に優しく栄養価の高い食事（具：タンパク質・ビタミン・ミネラルを意識、カフェイン/アルコール控えめ提案、消化に時間のかかる脂っこいものは避ける） |
| 高強度の運動をした日 | 運動後の回復を助ける食事（具：糖質＋たんぱく質の組み合わせ、水分・電解質補給の提案） |
| 運動量が少ない／休養日 | 摂取カロリーをやや抑えめにし、野菜中心・低GI食品を中心に提案 |

### 条件3：1日のカロリー目標と残り枠

- 基礎代謝＋活動量（Runkeeper由来の運動記録を含む）から1日の目標摂取カロリーを算出。
- 当日すでに記録された食事の合計カロリーを差し引き、「残りカロリー枠」を算出。
- 残り枠に収まる、かつ次の食事の標準的な配分（例：夕食なら1日の30〜35%目安）に
  近いカロリー帯の献立を優先して提案する。
- 残り枠が少ない場合は、低カロリーで満足感の高いメニュー（汁物・野菜中心等）を提案。

### 条件4：栄養バランス（PFC・主要栄養素）

- 直近の食事ログ（当日＋前日まで）を集計し、不足しがちな栄養素を補う方向で提案する。
  - タンパク質が不足気味 → 高タンパクなメニューを優先候補に
  - 野菜・食物繊維が不足気味 → 野菜量の多いメニューを優先候補に
  - 脂質・塩分・糖質が続けて多い → 控えめなメニューを優先し、軽い注意を添える
- 目安とする1日のPFCバランス（一般的な健康維持の範囲。プロフィールの目標で調整）：
  - タンパク質 13〜20% ／ 脂質 20〜30% ／ 炭水化物 50〜65%
  - 塩分は1日あたりの目安量を超えないよう、外食・加工食品が続いた場合は控えめな提案に寄せる

### 条件5：健康目標（プロフィール設定）

「減量」「維持」「増量・筋肉量アップ」のような単純な目標だけでなく、
**「減量」と「筋力アップ」を同時に狙う目標（ボディリコンポジション型）**にも対応する。
本アプリが主軸とする「2026年5月30日からの健康管理プログラム」（1年で-15kg＋筋力アップ）は
まさにこの型にあたるため、専用の方針を持たせる。

| 目標タイプ | 提案の方向性 |
|---|---|
| 減量のみ | カロリー収支をやや厳しめに、満足感重視（高食物繊維・高タンパク低脂質） |
| 増量・筋肉量アップのみ | カロリー・タンパク質をやや多めに配分 |
| 維持 | バランス重視で大きな偏りを作らない |
| **減量＋筋力アップ（ボディリコンポジション）** | 下記の方針で提案する |

**ボディリコンポジション型の提案方針**（本プログラムで採用）：

- カロリーは「緩やかな赤字」に留める（厳しい制限は避ける）。
  1年で-15kgという長期目標は、急激な制限よりも持続可能なペースに適している。
  目安として、1日の消費カロリーから大きく削りすぎない範囲（無理のない緩やかな
  カロリー収支）を基準とし、運動量に応じて微調整する。
- **タンパク質を最優先で確保する**（筋肉量の維持・向上のため、他の目標タイプよりも
  優先度を上げる）。トレーニングを行った日は特にタンパク質量を重視した献立を提案する。
- 筋力トレーニングを行った日・行う予定の日は、運動の前後で
  「炭水化物＋タンパク質」の組み合わせ（エネルギー補給と回復の両立）を提案する。
- 体重の増減だけでなく体脂肪率・筋肉量の推移（[2-2記録](02-screens-and-features.md)で
  表示）と突き合わせ、「順調に絞れているか」「筋肉量も保てているか」を踏まえた
  コメントを添える（例：「体重は順調に減っていますが、筋肉量を保つために
  今日はタンパク質をやや多めにとりましょう」）。

### 条件6：多様性・継続のしやすさ

- 直近数日と同じ料理・同じカテゴリ（揚げ物、麺類など）が続いている場合は、
  別カテゴリを優先的に提案し、メンネリ・栄養の偏りを防ぐ。
- 提案は「自宅で作れるメニュー」「コンビニ・外食での選び方」の両方を用意し、
  ユーザーの状況（自炊できるか否か）に応じて出し分けられるようにする
  （MVPでは固定の2案提示でも可。将来的にはユーザー設定で調整）。

## 3-4. 提案の出力イメージ

```
🍽 次の食事のおすすめ

① 鶏むね肉と野菜の蒸し料理（約480kcal / たんぱく質35g）
   理由：今日は運動量が多めなので、たんぱく質をしっかり。
        消化にも優しく、回復をサポートします。

② コンビニなら：サラダチキン＋具沢山スープ＋おにぎり1個
   理由：残りのカロリー枠（約550kcal）にちょうど収まる組み合わせです。

⚠ ひとことアドバイス：ここ2日、揚げ物が続いています。
   今日の夜は野菜多めのメニューがおすすめです。
```

- 提案は常に「理由」を添える（ユーザーが納得して選べるようにするため。
  ブラックボックスの提案は信頼を失う）。
- アレルギー該当品は理由の説明なく**最初から候補に出さない**（誤って表示しない設計）。

## 3-5. 精度・運用上の注意点

- 画像認識の精度には限界があるため、**確認・修正のステップを必ず挟む**
  （特に分量推定はAIに頼り切らず、ユーザーが「少なめ／普通／多め」を選べる程度の補助に留める）。
- 推定カロリー・栄養価には誤差がある前提で、提案は「厳密な指示」ではなく
  「方向性の提案」というトーンに統一する（数値を絶対視させない）。
- アレルギー情報は安全に直結するため、プロフィール未設定の場合は機能利用前に
  必ず入力を促す（未入力のまま提案を出さない）。
